# Refract: session-centered research, recall, synthesis, and analysis

## Record scope and evidence basis

Refract is a research workspace that joins activities researchers normally perform in separate tools: close reading of papers, source-linked note capture, cross-paper synthesis, retrieval practice, dataset inspection, and statistical modeling. This record is based on the live local checkout at `/Users/neeravch/Desktop/pdf-workspace`, inspected on October 12, 2026. Archived `code-export/` copies were excluded when determining the active implementation. No paid model calls or live external services were run for this review.

## The problem: research loses continuity when its evidence and decisions are split apart

The human problem is not simply that reading papers is slow. It is that a research argument is assembled across disconnected environments. A researcher reads in a PDF application, copies excerpts into notes, asks questions in an AI chat, compares papers in a document, practices recall elsewhere, uploads data to a notebook, and finally writes an interpretation that must somehow reconnect model output to the literature. Each move sheds context. Notes drift away from page references; comparisons become prose without a recoverable source set; review cards lose the passage that made them meaningful; and statistical results are discussed after the fact rather than interpreted through the research question and papers that motivated them.

Refract's main contribution is a continuity model for this work. A research session is not a folder label. It is a persistent object connecting a title, topic, context, papers, memberships, saved passages, question-answer cards, review attempts, datasets, analysis runs, and comparison output. The same session framing can shape document chat, determine the source set for comparison, scope a dataset, and provide literature evidence for interpreting model results. This converts a collection of useful features into one traceable research workflow.

The audience is broader than a student who wants summaries. Graduate researchers, literature-review teams, and applied analysts benefit when they must defend where a claim came from, why a variable entered a model, what evidence was available at the time, or whether a learner recalled rather than reread. In Industrial and Systems Engineering, the Battery Remaining Useful Life demonstration makes the value concrete: the researcher can study degradation literature, collect evidence, compare methods, audit a battery dataset, run baseline models, and interpret the resulting signals without severing the connection between the qualitative and quantitative work.

## What was built: five workspaces over one research state

The product exposes five distinct workspaces rather than treating every task as chat.

**Reader** keeps the PDF, session navigation, and assistant available together. A user can upload a PDF, navigate a generated or native table of contents, select a passage, ask for an explanation, simplification, key terms, a quiz, or a summary, and save the passage and response. Page-aware source badges return the user to the document. The viewer uses windowed page rendering, most-visible-page tracking, out-of-window navigation retries, and persistent selection highlighting so the research object remains present while the assistant is used.

**Index** turns those interactions into durable research memory. Saved entries retain page location, passage text, deep section path, concept tags, rhetorical facet, notes, synthesis, question origin, source chunk identifiers, and review state. The interface can group by section, concept, origin, or review pressure. It also contains repair paths for older cards whose standalone question or source context is weak. A semantic duplicate gate compares a proposed study question with active cards on the same highlight using normalized MiniLM embeddings and a cosine threshold of 0.85; the user can open the existing card, merge an answer, force-save, or dismiss. Duplicate cleanup is a soft-delete workflow so historical review rows remain joinable for research.

**Review** closes the loop that most reading assistants leave open. A card presents a canonical study question, asks the learner to answer from memory, captures a 1–5 confidence rating before grading, and records recall latency. The default is free recall with the source hidden. Where appropriate, the learner can reveal a cloze or assisted passage, and the system records `reveal_used` and `recall_mode` so assisted attempts are not silently mixed with free-recall data. Claude grades the answer against the source passage and expected answer on three 1–5 dimensions: core claim, supporting detail, and faithfulness. The combined score maps to an FSRS rating, updates stability, difficulty, state, and next due date, and stores both the raw grading result and derived scheduler input. The product therefore automates a sequence that would otherwise require manually creating cards, self-scoring recall, and updating a schedule.

**Compare** creates a persistent cross-paper research artifact. It combines a deterministic baseline with a generated analysis path. The generated path reads sampled PDF chunks first and treats saved notes as secondary anchors; it produces per-paper analyses, fixed scholarly dimensions, session-specific comparison axes, matrix cells, cross-paper insights, research gaps, and reader-guidance cards. Session title, topic, and context shape the comparison. Cache invalidation detects changes to the session framing or paper membership, and asynchronous generation records stage, progress, heartbeat, error, and stale state. This is notably more structured than asking a model to “compare these PDFs” and receiving disposable prose: the implementation makes the question, source set, dimensions, contrasts, gaps, and generation state inspectable.

**Stats** extends the same session into quantitative work. A dataset is uploaded as a session-scoped artifact and its schema, shape, and storage identity are persisted. The current staged run contains setup, dataset profile, initial audit, and baseline regression checkpoints. The profile reports row and column counts, duplicates, missingness, inferred kinds, numeric summaries, target candidates, role hints, and variable semantics. The audit checks missingness, constants, identifier-like variables, target correlation, probable leakage at `|Spearman rho| >= 0.97`, and predictor redundancy at `|rho| >= 0.95`. Regression is gated on human acceptance of the audit rather than firing automatically. It then compares a train-mean baseline, standardized linear regression, and a Random Forest regressor using MAE, RMSE, and R-squared. The active code uses an 80/20 split with `random_state=42`; the forest uses 240 trees, maximum depth 14, minimum leaf size 2, median imputation, and single-process execution. Predictor exclusions, step versions, acceptance, stale status, assumptions, warnings, metrics, coefficients, feature importances, artifact manifests, and review decisions are retained with the run.

## Architecture and important implementation decisions

The frontend is React 18 with Vite, Zustand, Axios, React Markdown, and `react-pdf`. The backend is FastAPI with SQLAlchemy, Alembic, PostgreSQL, Pydantic settings, and Uvicorn. S3-compatible object storage holds uploaded files and generated artifacts. ChromaDB holds document vectors. Analytics use pandas, NumPy, scikit-learn, Matplotlib, Seaborn, and OpenPyXL. Claude is called directly for document response generation, comparative synthesis, ontology/classification, card generation, and recall grading; OpenAI is used for Whisper transcription. The code does not hide the product behind a generic orchestration framework: the important domain logic is visible in custom services, typed routes, stored state, and explicit prompts.

The retrieval path is concrete. PyMuPDF extracts text page by page. `tiktoken` with `cl100k_base` makes 512-token chunks with 50-token overlap. `all-MiniLM-L6-v2` produces L2-normalized embeddings, and ChromaDB stores them in the cosine-distance `pdf_chunks` collection with `pdf_id`, page number, and chunk index. A document question retrieves the top five chunks filtered to the active PDF. When all retrieved distances exceed 1.3, highlighted questions remain bound to the selected passage, obvious document questions stay on the document path, and genuinely external questions can use a separately labeled Tavily path. Responses return page and chunk metadata to the UI. This supports the bounded positive claim that Refract implements source-constrained retrieval with page-level provenance and evidence-only fallback paths. It is not described here as an independent claim-by-claim citation verifier.

Several design decisions show methodological discipline. Session suggestions are deterministic, editable, and safe to ignore rather than silently model-generated. PDFs can belong to more than one session through a membership table while retaining a primary-session compatibility pointer. Comparisons become stale when their source set or framing changes. Statistical runs require review and acceptance between audit and modeling steps. Card deletion is archival where research joins must survive. Rubric version, prompt version, exact model string, source-reveal mode, raw scores, and scheduler transitions are recorded because changing any of them changes the meaning of later analysis.

The author also designed recovery and legacy-repair paths instead of assuming a clean greenfield database. Backfill routes establish default sessions, older question cards can be reframed or converted to notes, source context can be reattached, duplicate cards can be merged without deleting research history, and migrations provide forward and downgrade paths. These choices reduce the practical risk of evolving a research prototype while preserving longitudinal records.

## Methodology: literature-led product design and testable instrumentation

The project was developed as a system-building thesis with a deliberately narrower empirical arm. The research folder surveys spaced repetition and FSRS, testing-effect evidence, LLM grading, pedagogical language models, scholarly-reading interfaces, confidence calibration, and authentic classroom studies. Its gap analysis distinguishes components that already exist from the specific integration being investigated. The strongest thesis idea is not that RAG, FSRS, or LLM grading is individually new. It is the capture-to-schedule-to-test-to-grade-to-reschedule loop over user-selected academic passages, with source-grounded grading and analyzable review records.

That literature review directly shaped the product. Testing-effect and generative-learning findings motivated answering before reveal. Calibration research motivated collecting confidence before the grade is shown. FSRS provides the scheduling model, but the scheduler signal comes from a structured assessment rather than the learner's unexamined “again/hard/good/easy” judgment. Work on scholarly reading motivated rhetorical facets, passage-level evidence, and cross-paper comparison. Cautionary work on learning versus immediate performance led the research plan to separate implemented instrumentation from a future claim about delayed retention.

The grading design is intentionally reproducible. The active service pins `claude-sonnet-4-20250514`, sets temperature to zero, uses rubric version `v1.0` and prompt version `grading_v1.0`, passes source chunks and an expected answer, requests JSON-only output, and stores the model's confidence, rubric hits, missing concepts, and feedback. The 1–5 overall result is preserved alongside the 1–4 FSRS conversion so researchers can revise the mapping after the fact without rerunning model grading. A `human_grades` table and blinded export path support an inter-rater-reliability substudy rather than assuming that model judgment is ground truth.

Evaluation is layered. Backend tests cover health, PDF upload and streaming, table-of-contents shape, chat with selection and history, source schema, and error cases. Playwright probes cover session creation and editing, sidebar placement, workspace navigation, index/review behavior, comparison payloads, legacy repair, recall-first interaction, duplicate handling, and Stats layout. Stored historical reports show a nine-of-nine UI evaluation for loading, PDF selection, formatted chat, five visible source badges, Index navigation, adaptive concision, and 1440/1024 viewport overflow; a one-of-one multi-turn concision case also passed. The deep-fix status record reports six-of-six duplicate-flow checks and eight-of-eight recall-first checks. These are useful verification results, not user-outcome evidence, and they are dated artifacts rather than a fresh test run performed for this record.

## Results and why the work is notable

The strongest achieved result is an unusually complete traceability chain. A user can move from a paper page to a selected excerpt, a grounded response, an indexed card, a recall attempt, a rubric result, and a new review date without losing the document and chunk identifiers that anchor the sequence. On the quantitative side, the user can move from a session goal and dataset to a profile, a leakage/redundancy audit, an accepted feature frame, three model comparisons, saved metrics, and literature-alignment notes. Refract therefore automates both research-memory maintenance and a first-pass analytical audit while preserving human checkpoints.

The system is also notable for making provenance visible at several levels rather than adding citations cosmetically at the end. Document answers return pages and chunks. Comparison output is fingerprinted to its framing and paper set. Recall grades retain source text, prompt/rubric/model versions, reveal behavior, and scheduler transitions. Statistical variable rows distinguish data-derived evidence, domain or preset knowledge, literature support, and unresolved meaning. These structures let a later reviewer ask not only “what did the model say?” but “which source, version, state, and decision produced this result?”

The eight-page thesis-positioning document frames Battery Remaining Useful Life as the demonstration case and cites prior notebook metrics of RMSE 25.61 and R-squared 0.993. Those values are evidence from the author's earlier validated analysis, not a newly measured Refract run in this review. The directly verified Refract result is the implemented, review-gated pipeline that computes its own mean, linear, and forest metrics and retains them with exact inputs and assumptions. That is already meaningful: it replaces an opaque “run model” button with a staged notebook-like record that makes dataset quality, leakage risk, predictor decisions, baseline value, and interpretation inspectable.

For researchers, the improvement is less reconstruction work and fewer undocumented transitions. For learners, it is a move from passive highlighting to source-grounded recall practice with feedback and scheduling. For advisors or reviewers, it is a clearer audit trail across literature and analysis. For an organization conducting applied research, it offers a pattern for keeping qualitative evidence, quantitative evidence, and the decisions joining them in one recoverable system.

### Interpretation supported by the evidence

- Refract's most defensible differentiator is not a single algorithm; it is the session-centered integration of research synthesis, active recall, and review-gated quantitative analysis with recoverable provenance.
- The implementation reduces tool-switching and manual reconstruction because the artifact relationships are stored, not merely described in UI copy.
- The instrumentation is strong enough to support a future retention study and human-grader agreement study. It does not by itself establish improved long-term retention or production predictive-maintenance performance.
